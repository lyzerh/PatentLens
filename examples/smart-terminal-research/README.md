# 智能终端散热技术研究演示（Synthetic）

本案例模拟一家智能终端企业整理两种热界面材料方案。**EP9000001A1 与 EP9000002A1 均为虚构编号；所有标题、权利要求及研究记录均为 Synthetic。** 数据中的 EPO 形状 URL 仅是现有冻结数据格式所需的合成占位符，不能作为真实 EPO 来源链接或公开文献证据。报告中的哈希只校验本地合成文本的一致性。

## 研究任务与实际发现

研究者在资料库登记两条合成记录，用免费 Rules 生成机器候选，查看原文、要素和限定，之后在检索页面选择 A/B 比较，将双方快照与人工差异保存进同一研究集合。浏览器实际下载了 [Markdown 报告](research-report.md) 和 [JSON 报告](research-report.json)。

双方 Claim 1 都写有热界面材料、非硅树脂、相变材料、增塑剂和导热颗粒填料。人工演示备注指出：A 的增塑剂比例为树脂质量的 25–50%，B 为总组成质量的 30–55%；这两个百分比不能直接按数值大小判断等同。A 的粒径限定为严格小于 25 µm，B 为严格小于 20 µm。双方逐字引文保存在报告中。机器字段和候选对应均未经过专业语义核验；人工备注署名 `Synthetic researcher`，仅表示演示操作。

## 复现

1. 安装 Node.js 24+，运行 `npm ci` 和 `npm run demo:portfolio`，打开打印出的本地地址并进入 `/workspace`。演示服务只使用本地 Synthetic 数据；无需 API Key。
2. 在「专利资料库」导入 [demo-data.json](demo-data.json)。该文件保存两条合成记录。正式标题和内部研究资料分开维护。
3. 在「技术解析」分别选择两条记录，运行免费 Rules，查看 Claim 1、技术要素、限定、关系及原文定位，保存机器候选。
4. 在「技术检索」的高级区域对两条合成记录执行免费 Rules 批量入库；搜索 `plasticizer`，设为 A/B，进入比较。检索只覆盖已建立的特征记录。
5. 在比较页查看候选和未对应项。人工研究区使用双方 Claim 1 中连续逐字片段记录上述比例基准差异，创建研究集合并保存；机器候选不能代替人工判断。
6. 回到检索页选择两条已入库记录，将两份 Feature Snapshot 加入同一集合。刷新「研究项目」，导出 Markdown 与 JSON。新运行会产生新的记录 ID 和时间戳，技术内容应与示例一致。
