# PatentLens 企业研究界面：下一轮最小改造

基于 `10b0c16` 页面及业务代码核对。本轮只规划，不修改 UI。能力测试材料保存在本机忽略目录；A/B 模型语义能力**未验证**。

## 当前问题与优先顺序

| 优先级 | 真实问题与业务影响 | 最小改法、可复用处 |
| --- | --- | --- |
| P0 | `/pilot` 有正式标题、申请人、摘要和人工标签；`/patent-repository` 主要围绕已有 Feature Record。未解析登记文献不能自然形成可浏览的专题卡片，用户容易把“特征库无结果”误读成“资料库无此专利”。 | 在现有 `/pilot` 登记列表或工作台的集合入口，给已登记文献加展开详情：正式标题、公开号、申请人、摘要可用性、人工标签、来源和“未解析”状态。复用登记 `state` 与 `registry-context.js`；不创建第二份专利数据。入口从集合返回登记详情，保持记录身份校验。 |
| P0 | `/patent-features` 已能点击字段定位 Claim 1，也显示数值单位和比例基准，但机器字段、Coverage、Schema 等诊断并列；普通 IP 用户难以先看到技术组成和仍需核查处。 | 在现有 `renderStructure` 与页面 CSS 中先呈现技术对象→要素→限定→关系及原文联动；把 Coverage／格式与证据诊断折叠为“核查详情”。原字段、原文定位和审核状态不变。解析后保留现有检索、比较及集合链接。 |
| P1 | `/patent-compare` 的机器候选可显示两侧要素、限定与证据；人工研究可独立保存，但原始 Claim 1 双栏展开与分层比较尚未成为同一个顺畅的主流程。 | 复用 `patent-compare.js` 的 A/B 来源和 `showEvidence`，把双方 Claim 1 以可展开双栏放在候选对应前；按“共同主题／组成／限定差异／未匹配／人工备注”排布。人工入口继续复用 `manual-research.js` 的逐字引文校验和版本保存，不自动生成技术等同判断。 |

## 数据和页面边界

- **可直接复用：**`/pilot` 的原始标题、申请人、摘要、人工标签与修订履历；`/patent-repository` 的 Feature Record、来源哈希、查询与集合；`/patent-features` 的原文定位、要素／限定／关系；`/patent-compare` 的 A/B 记录与证据；`patent-collections.ts` 的人工及机器快照导出。
- **预计涉及：**`public/pilot.js`、`public/pilot.css`、`public/patent-features.html/.js/.css`、`public/patent-compare.html/.js/.css`，以及现有 `public/patent-repository.js` 的集合返回链接；若现有 API 无法按身份关联，先核查 `src/pilot/service.ts`、`src/pilot/patent-collections.ts`，避免用同一公开号误连不同来源版本。
- **无需 LLM：**专题卡片、原文与技术字段分层、双栏 Claim 1、人工差异和引文、集合保存与导出，均有独立企业价值。
- **依赖真实能力测试：**AI 自动技术短标题／简介／标签建议，以及自动双专利差异摘要。未获 A/B 的真实输出与人工核验前，不接产品卡片或比较主流程。人工短标题／简介可规划为登记修订字段，但当前没有专用字段与审核流程，不能假称已支持。
- **保持实验属性：**`/patent-search` 是外部检索和粘贴测试区，不自动登记；`/pilot` 的 AI 分类、模型对照及价值验证仍为高级实验，不与企业研究集合混作已核实结论。

验收标准：首次打开集合能辨认每篇专利及资料状态；阅读 Claim 1 后可追到具体要素与限定；双栏比较能保存人工逐字证据；未解析与机器候选状态清楚，不产生自动付费请求。
